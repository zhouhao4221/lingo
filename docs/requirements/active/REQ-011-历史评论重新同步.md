## 一、需求描述

### 1.1 背景

GPCM 已确认 Gitea 评论全部转给反馈提交人，并在本地配置 `GiteaConfig.ReplyMode = ReplyAll`（SDK 默认仍为 `ReplyMarked`，不改）。
GPCM REQ-055 开发核实：评论是否对外在**同步时**按当时的 ReplyMode 判定并存库；定时对账（`worker.reconcileComments`）按游标增量拉取
`ListRepoComments(since)`，游标只前进。所以切换 ReplyAll 之前已保存为内部的普通评论不会回补，除非 Gitea 上被再次编辑。

核实结论：现有代码中没有能重读单个 Issue 全部评论并按当前配置重新判定的公开能力。可复用的部分包括：
- `worker.commentUpdate`：ReplyMode 判定、`/reply` 前缀、机器人识别，Webhook 与对账共用
- `ticket.Sync.ApplyComment`：按 Gitea 评论 ID 去重，旧版本不覆盖，已删除的不恢复，对外改内部时清除变更流正文，记审计
- `gitea.Client.ListIssueComments`：读单个 Issue 的全部评论，驳回关闭任务已在用

本需求只把这几块串起来，提供一个管理侧、按工单调用的重新同步入口。

### 1.2 范围与边界

- **本期包含**：Go `ResyncTicketComments`、REST `POST /tickets/{id}/comments/resync`；单测、集成测试、文档
- **本期不做**：
  - 批量或全项目回补：接入方用 `ListTickets` 分页逐张调用
  - 修改默认 ReplyMode
  - 根据 Gitea 列表中缺少某条评论推断删除：删除仍以 Webhook 为准，避免 Issue 重新关联等情况下误删
  - MCP 工具
  - 写 Gitea

## 三、业务规则

| 类型 | 规则 | 说明 |
|------|-----|------|
| 权限控制 | 仅 reviewer / admin | 其他角色 `ErrForbidden`，先于查找，不暴露工单是否存在 |
| 权限控制 | 项目范围 | 工单须在 `User.Projects` 内（为空时为 `Config.Projects` 全部，与 `GetTicket` 相同）；否则与不存在一样 `ErrNotFound` |
| 隔离 | 只读该工单的主 Issue | 只请求 `工单.Repo#IssueNumber` 的评论；写入时再核对 Issue 关联的就是该工单（`TicketID`），否则跳过 |
| 判定 | 按当前配置 | 是否对外按当前 `GiteaConfig.ReplyMode`（`all` 时全部非机器人评论对外；`marked` 时只有 `/reply` 或 `<!-- lingo:public -->`）；对外的去掉 `/reply` 前缀 |
| 判定 | 机器人过滤 | 机器人账号（大小写不敏感）的评论跳过；账号未获取到时最多等 5 秒，仍未获取则返回 `ErrConflict`（稍后重试），不会把灵工转发的补充当成研发评论导入 |
| 去重 / 编辑 | 同 Webhook | 按 Gitea 评论 ID 去重；正文或判定有变化才更新并记审计（`delivery=resync`）；旧于已保存版本的不覆盖、灵工已记为删除的不恢复，这两种未写入的情况计入 `Unchanged`，不记审计、不改可见性计数；对外改为内部时清除变更流中的正文 |
| 合并 | 不跨工单 | 已合并的工单没有自己的 Issue，返回 `ErrConflict`；目标工单的评论对外后，被合并工单的提交人照常看到（规则不变） |
| 通知 | 默认不发 | 历史回补不通知提交人，也不写 `ticket.comment` 变更流事件；`Notify=true` 时与 Webhook 一样，为新变为对外的评论发事件 |
| 幂等 | 重复调用 | 无变化时全部计入 `Unchanged`，不新增审计、评论或事件 |
| 非功能 | 只读 Gitea | 一次 `GET /repos/{owner}/{repo}/issues/{n}/comments`（Gitea 该接口不分页）；不写 Gitea |
| 错误 | 无可同步的 Issue | 无关联主 Issue（待确认、待建单、已合并、直接答复等）、Gitea 未配置、Issue 在 Gitea 上已不存在 → `ErrConflict`；其他 Gitea 错误原样返回（REST 500） |

## 四、接口契约

### 4.1 Go

- `func (l *Lingo) ResyncTicketComments(ctx context.Context, u User, id int64, o CommentResyncOptions) (CommentResync, error)`
- `CommentResyncOptions{ Notify bool }`
- `CommentResync{ TicketID int64; Repo string; Issue int64; Fetched, Bot, Added, Updated, Unchanged, Skipped, Published, Unpublished int; Notified bool }`
  - JSON：`ticket_id`、`repo`、`issue`、`fetched`、`bot`、`added`、`updated`、`unchanged`、`skipped`、`published`、`unpublished`、`notified`

### 4.2 REST

`POST /tickets/{id}/comments/resync`，`Content-Type: application/json`，body 可省略或为 `{"notify":false|true}`

- 200：`CommentResync` JSON
- 401 未认证；403 `forbidden`（非 reviewer / admin）；404 `not_found`（不存在或不在项目范围）；409 `conflict`（无关联 Issue、Gitea 未配置、机器人账号未就绪、Issue 已删除）；500 其他 Gitea 错误

## 五、测试要点

- [x] 回补：ReplyMarked 下只有 `/reply` 对外；切换 ReplyAll 后内部评论变为对外（Updated 1、Published 1），提交人可见，默认无 `ticket.comment` 事件
- [x] 幂等：再次执行全部 Unchanged，审计与评论行数不变；机器人评论不导入、无重复行
- [x] 编辑 / 删除：Gitea 上编辑后的正文写回；灵工已删除的评论不恢复
- [x] 未写入不计变化：已删除评论在 Gitea 上正文不同（ReplyAll）、已删除且原本对外的评论在 marked 下改判内部、乱序旧版本，各重复两次均为 `Unchanged`，审计与变更流行数不变，评论仍不可见
- [x] 隔离：只读该工单的主 Issue、不写 Gitea；其他工单（同项目、其他项目）不产生评论；Issue 关联到其他工单时跳过（单测）
- [x] 授权：external、agent、未知角色 403（含探测不存在的 ID）；越项目 reviewer / admin 与不存在 404；无 Issue / Issue 已删除 409；REST 401 / 403 / 404 / 409
- [x] Notify：为新变为对外的评论发事件，提交人变更流可见
- [x] 正常同步回归：回补后 Webhook 新评论照常保存并通知，机器人评论照常忽略；全量既有测试通过
- [x] worker：与对账相同的 commentUpdate（ReplyAll / ReplyMarked、`/reply`、机器人大小写）；未配置、账号未知、Gitea 读取失败
