## 一、需求描述

### 1.1 背景

GPCM #787 要在接入方后台做"反馈管理"页：按项目、状态、类型、关键词筛选、分页浏览工单。v0.10.0（origin/main def5290）的公开列表只有
三种，都不适合做管理列表：

| 现有 API | 范围 | 不足 |
|---|---|---|
| `ListMyTickets`（`GET /tickets/mine`） | 本人提交的 | 后台看不到别人的 |
| `ListVisibleTickets`（`GET /tickets/visible`） | 本人 + 同事（external） | reviewer / admin 只含本人；只能按状态 / 项目筛选 |
| `ListTriage`（`GET /triage`） | 待确认（reviewer / admin） | 只有 pending_triage |

领域层已有 `internal/ticket.Service.Search` / `searchScope`（知识问答检索用），按角色填写可见范围（与 `ticket.Readable` 一致），支持项目、仓库、
类型、状态、关键词、时间、游标。本需求把它以公开 API 暴露，**不新增任何权限规则**。

### 1.2 目标

- **功能目标**：公开 Go `ListTickets` 与 REST `GET /tickets`，返回一页工单 + 总数 + 下一页游标
- **效果目标**：接入方用一个接口即可做反馈管理列表；各角色看到的范围与 `GetTicket` / 知识问答完全一致，不放宽读写

### 1.3 范围与边界

- **本期包含**：Go `ListTickets`、`TicketListFilter`、`TicketPage`；REST `GET /tickets`；单测、集成测试、文档
- **本期不做**：MCP 工具（研发 Agent 已有 `search`/问答路径，按需另提）；新的权限规则或角色配置；按提交人 / 处理人筛选；排序方式选择（固定新的在前）；
  导出；修改 `ReplyMarked`、评论策略、自动转工单
- **隔离口径**：按 lingo 项目（`User.Projects`）隔离，不是接入方公司 / 组织隔离；lingo 不替接入方提权，`User.Role` / `User.Projects` 由接入方映射

## 三、业务规则

| 类型 | 规则 | 说明 |
|------|-----|------|
| 权限控制 | external 默认只含本人 | `IncludeShared=true` 时另含 `Config.TicketAudience` 放宽的同事工单（REQ-004 既有、只读，`mine=false`）；未配置回调、回调出错时只含本人；默认不调用回调 |
| 权限控制 | agent 只含已转出 | `User.Projects` 内状态不为 pending_triage / answered / merged / rejected 的；`Mine=true` 时为空（agent 不提交工单） |
| 权限控制 | reviewer / admin 仅授权项目 | `User.Projects` 内全部；`User.Projects` 为空时为 `Config.Projects` 声明的全部项目（与 `GetTicket`、`ListTriage` 相同的既有语义）；`Mine=true` 收窄到本人 |
| 权限控制 | 范围外项目 | `Project` 不在调用者范围内（含配置已删除的项目）返回空页，不区分不存在与无权 |
| 权限控制 | 无权限 | 角色未知、external 无 `User.ID` → `ErrForbidden`（403）；未认证 → 401 |
| 权限控制 | 范围不可伪造 | 范围由 `searchScope` 按角色覆盖，筛选只收窄 |
| 数据校验 | 筛选 | 类型、状态取值同 `Ticket`；时间字段 created / updated / forwarded；仓库须为 owner/name；关键词按空白拆分、最多 10 个、每个最多 100 字；不合法 → `ErrInvalidInput`（400） |
| 数据校验 | 分页 | 按 ID 降序，`BeforeID` 游标；`Limit` 默认 50、最多 200；`NextBefore=0` 表示无下一页（精确：多取一条判断） |
| 非功能约束 | 总数 | `Total` 不受游标与条数影响，与列表分两次查询，并发写入时可能略有出入 |
| 非功能约束 | 兼容 | 只新增类型、方法与路由；无迁移；现有接口行为不变 |

## 四、接口契约

### 4.1 Go

```go
type TicketListFilter struct {
	Project       string     // 为空不限（仍限 User.Projects）
	Repo          string     // "owner/name"
	Type          TicketType // consult | bug | feature
	Statuses      []string   // 任一状态
	Keyword       string     // 空白分词，各词须同时命中标题或正文
	Mine          bool
	IncludeShared bool       // 仅 external
	TimeField     string     // created（默认）| updated | forwarded
	From, To      time.Time  // To 不含
	BeforeID      int64
	Limit         int        // 0 → 50，最多 200
}

type TicketPage struct {
	Tickets    []Ticket `json:"tickets"`
	Total      int      `json:"total"`
	NextBefore int64    `json:"next_before"`
}

func (l *Lingo) ListTickets(ctx context.Context, u User, f TicketListFilter) (TicketPage, error)
```

`Ticket` 为既有公开结构（id、project、repo、type、title、body、status、user_id、user_name、issue_url、fixed_tag、deployed_at、created_at、
updated_at、triage_since、mine），不含邮箱。

### 4.2 REST

`GET /tickets?project=&repo=&type=&status=a,b&q=&mine=&shared=&time_field=&from=&to=&before=&limit=`

- `status` 逗号分隔、表示任一（重复的去重）；`q` 按空白拆词（最多 10 个、每个最多 100 字）；`mine` / `shared` 只接受 true / false / 1 / 0（其他 400）；`time_field` 默认 created，`forwarded` 不传 from / to 时只含已转出的；`from` / `to` 为 RFC 3339，`to` 不含；`before` 为上一页的 `next_before`；`limit` 默认 50、最大 200
- 200：`{"tickets":[Ticket...],"total":N,"next_before":ID}`（空时 `tickets` 为 `[]`，`next_before` 为 0）
- 400 `bad_request` / `invalid_input`、401、403 `forbidden`

- [x] 角色范围：external 默认本人 / shared 含同事 / mine；agent 已转出、项目内、mine 为空；reviewer 声明项目全部、mine、`User.Projects` 收窄；admin 收窄

- [x] 范围不可伪造：传入的 Scope / UserIDs / ForwardedOnly 被覆盖
- [x] TicketAudience：默认与非 external 不调用；出错按只含本人
