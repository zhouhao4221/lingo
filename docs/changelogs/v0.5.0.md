# v0.5.0（2026-11-24）

模型与 Gitea 的连接配置可以存入数据库，由有权限的人经接口查看、修改与测试，**不用重启**即生效；代码中 `lingo.Config` 给出的值仍然优先。`lingo.New` 不再要求 Gitea 地址与令牌，缺失时以「未配置」状态运行，配置好后自动恢复。公开 API 只增不改；新增迁移 `0004_settings.sql`，升级后需执行 `lingo.Migrate`。

要求：Go 1.24+、PostgreSQL 13+、Gitea 1.22+（同 v0.4.0）。

## 新功能 (Features)

- **连接配置存入数据库**（#36，REQ-005）
  - **能配置的内容**：主模型、轻量模型（类型 `openai` / `deepseek`、接口地址、模型名、API Key）；Gitea 地址、机器人令牌、Webhook 密钥、自动注册 Webhook 与回调地址、拒绝重定向。`LabelPrefix`、`ReplyMode` 仍只能在代码中配置。
  - **接口**：Go 方法 `ConnectionSettings` / `UpdateConnectionSettings` / `TestConnectionSettings`；REST `GET` / `PUT /settings/connections`、`POST /settings/connections/test`。不提供 MCP。
  - **权限**：新增 `Config.AuthorizeSettings(ctx, u, write)`，不配置时只允许 admin。
  - **优先级**：代码中有值的项来源为 `config`，修改返回 `ErrConflict`；没有的读数据库。模型按槽位判断；布尔项代码中为 `true` 时才锁定。
  - **查看**：每项标出来源（`config` / `database` / `unset`）；密钥只返回是否已设置与掩码（20 个字符以上为 `sk-****abcd`，更短的为 `****`）；`applied` 标出本实例是否已在使用这份配置。
  - **修改**：按字段修改（不传 = 不改，空串 = 清除）。地址的协议或主机变了，必须同时重填令牌 / API Key，避免把已保存的密钥发往新地址；清空地址时一并清空数据库中的密钥。
  - **连通测试**：不保存；Gitea 读取机器人账号与版本，模型发一次简短对话；失败原因已脱敏（只含类别与 HTTP 状态码）。
  - **生效**：保存后当前实例立即生效，其他实例 30 秒内生效（`Run` 定时检查，Handler 与 Go 方法在使用时按需检查）；进行中的请求使用开始时的配置。Gitea 连接项变化且开启自动注册时，补跑自检，把新的密钥与回调地址同步到各仓库的 Webhook（指向旧回调地址的 Hook 改到新地址）。
  - **审计**：每次保存写一条应用日志（修改人、类别、字段名、版本），不含值。
- **未配置状态**：`New` 不再要求 `Config.Gitea.BaseURL` 与 `Token`。缺失时 Webhook 返回 503，建单等 Gitea 任务暂缓（不计失败，处理中途被清空也改为推迟），自检只报 `config` 警告；配置好后自动恢复。代码中只给了地址或令牌之一时会告警。
- **自动注册校验调整**：`AutoRegisterWebhook` 的回调地址与密钥可以来自数据库，`New` 不再要求代码中同时给出；生效后缺任何一个时，自检不自动注册并报告错误（不会把空密钥写进 Gitea）。

## 数据库

- **新增迁移 `migrations/0004_settings.sql`**：表 `lingo_settings`，按类别（`model` / `gitea`）各一行，jsonb 内容、版本号、修改人、修改时间。0001–0003 未改动。
- **密钥明文存储**：能读取 `lingo_settings`（含备份、只读副本）的人都能拿到密钥，请收紧数据库账号与备份的访问。
- **升级需执行迁移**：在发布流程中调用 `lingo.Migrate(ctx, db)`，可先用 `lingo.CheckMigrations` 确认就绪。0004 随本版本发布，之后不再修改。

## 升级

```sh
go get github.com/zhouhao4221/lingo@v0.5.0
```

- 升级后执行 `lingo.Migrate(ctx, db)`，应用 0004。
- 代码中传了完整 `Config.Gitea` 与 `Config.Model` 的接入方行为不变。要改为在后台配置，去掉代码中对应的值，经 `PUT /settings/connections` 写入即可；建议同时配置 `Config.AuthorizeSettings`。
- 以前依赖 `New` 在缺少 Gitea 配置时报错来发现配置问题的，现在改为观察启动日志中的告警或 `SelfCheck` 的 `config` 项。
