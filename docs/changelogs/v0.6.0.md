# v0.6.0（2026-11-24）

接入方可按自己的规则（如同部门、同团队）让 external 用户**只读查看同事的工单**：新增 `Config.TicketAudience` 回调与可见工单列表，知识问答与版本问答跟随放宽。公开 API 只增不改；**无数据库迁移**。不配置回调时行为与 v0.5.0 完全一致。

要求：Go 1.24+、PostgreSQL 13+、Gitea 1.22+（同 v0.5.0）。

## 新功能 (Features)

- **同事可见**（#38、#39，REQ-004）
  - **范围回调**：`Config.TicketAudience(ctx, u) (TicketAudience, error)` 返回 external 用户额外可见的提交人（`UserIDs`）。只对有 `User.ID` 的 external 调用，每个读请求最多一次、不缓存；去重、去掉本人，最多取前 `MaxTicketAudience`（1000）个，实际截断时记 Warn；回调出错按未放宽处理并记 Warn，请求不失败。
  - **只读、不超出 `User.Projects`**：`GetTicket` 与详情、`ListTicketComments`（对外评论）、版本关联的工单（`GetRelease`）跟随放宽。
  - **可见工单列表**：Go `ListVisibleTickets(ctx, u, VisibleTicketFilter)`、REST `GET /tickets/visible?project=&status=&before=&limit=`、MCP `list_visible_tickets`，返回本人的与同事的工单（限定在 `User.Projects` 内）。
  - **`Ticket.Mine`**：标记是否调用者本人提交；`AuthorizePerspective` 收到的工单同样填写。
  - **不跟随放宽**：留言、补附件、补充视角、确认留言（对同事工单返回 `not_found`），附件（同事查看详情时附件列表为空），`ListEvents` / `Notifier`，需求视角（未配置 `AuthorizePerspective` 时）。
  - **合并工单**按提交人判断：同事的工单被合并进他人的主工单时，主工单不随之可见。
- **知识问答跟随放宽**
  - 查找、统计与汇总包含同事的工单；问"我的"时只含本人。
  - 同事的工单向模型发送提交人姓名（`submitter`），以便回答"由谁提交"；其他角色、其他工单仍不发送提交人身份。
  - 要求对同事的工单留言时回复"只能对自己提交的工单留言"，不提出待确认操作。
  - 历史会话：查看消息与送给模型的历史对话中，引用的工单按当前范围重新判断，已不可见的只保留编号（已生成的回答正文不做处理）。
