# v0.9.0（2026-11-25）

业务数据工具（只读）：接入方在 `Config.Tools` 注册的只读工具，现在由知识问答、MCP 与 Go 方法 `CallTool` 以**调用人的身份**调用，灵工负责权限预校验、参数校验、脱敏、截断、超时、并发上限、熔断与审计。公开 API 只增不改；新增迁移 `0007_data_requests.sql`，升级后需执行 `lingo.Migrate`。**本版本有行为变化，升级前请阅读「行为变化」。**

要求：Go 1.24+、PostgreSQL 13+、Gitea 1.22+（同 v0.8.0）。不需要数据库扩展。

## 新功能 (Features)

- **业务数据工具（只读）**（#50，REQ-008）
  - **三种入口**：知识问答新增业务数据意图（每次提问最多调用一个工具，结果作为数据交给模型作答，引用 `citations.tools` 只记工具名）；MCP `tools/list` 列出调用人可调用的业务工具并可直接调用；Go 方法 `CallTool(ctx, u, name, input)`。
  - **权限**：`User.Scopes` 含 `Tool.Scope` 才可见、可调用；`Call` 收到当前 `lingo.User`，**业务侧必须在 `Call` 内二次鉴权**。无权调用、工具不存在、结果声明的归属项目不可访问三者对外相同（`ErrNotFound` / MCP `unknown tool`）。
  - **参数**：输入须为完整的单个 JSON 对象；校验 `required` 与基本类型，`integer` 与 Go 标准整型解码一致；不做类型转换。错误信息只含参数名与期望类型。
  - **结果**：按 `Sensitive` 路径脱敏（字段名不区分大小写），超过 8KB 截断；原始结果不写入会话、知识库、审计与日志。
  - **超时与熔断**：默认 10 秒，`Tool.Timeout` 最多 60 秒；每个工具 8 个、合计 64 个在途调用；同一工具 5 分钟内连续 5 次技术故障暂停 1 分钟（只在当前实例内），之后放行一次试探。
  - **审计**：每次调用先写记录再执行（写不进不调用），不含结果与错误原文，保留 180 天。`ListDataRequests` / REST `GET /data-requests`：本人记录，以及 reviewer / admin 在其 `User.Projects` **明确列出**的项目内的记录（归属项目只取 `Call` 返回的 `ToolOutput.Project` 声明；`User.Projects` 为空不授予跨用户审计）。
  - 新增公开 API（只增不改）：
    - 方法：`(*Lingo).CallTool(ctx, u User, name string, input json.RawMessage) (ToolResult, error)`；`(*Lingo).ListDataRequests(ctx, u User, f DataRequestFilter) ([]DataRequest, error)`
    - 类型：`ToolOutput{Project, Data}`（`Call` 可选返回值）、`ToolResult{Tool, Data, Text, Truncated}`、`DataRequest`、`DataRequestFilter{Tool, UserID, Status, Since, Until, Before, Limit}`、`ToolCitation{Name}`
    - 字段：`Tool.Timeout`；`Citations.Tools []ToolCitation`（JSON `tools`，没有调用工具时省略）
    - 错误：`ErrToolUnavailable`（REST 503 `tool_unavailable`）、`ErrToolFailed`（REST 502 `tool_failed`）
    - REST：`GET /data-requests?tool=&user_id=&status=&since=&until=&before=&limit=`
    - MCP：`tools/list` 追加调用人可调用的业务工具，调用规则同 `CallTool`
    - 用量类型：`data_answer`

## 行为变化

1. **已注册的工具开始被真实调用**：v0.8.0 及以前 `Config.Tools` 不生效；升级后，调用人 `User.Scopes` 含其 `Scope` 时，工具会被问答、MCP 与 `CallTool` 真实调用，产生真实的业务查询与审计记录。
2. **不合格的工具被忽略并告警**：名称不合法、`Mode` 不是 `read`（如 `write`）、`Scope` 为空或含空白、`InputSchema` 不是 JSON 对象、`Call` 为空、`Timeout` 为负或超过 60 秒、与内置 MCP 工具或先注册的工具重名的，被忽略并记 Warn `Config.Tools entry ignored`；`New` 照常成功，不覆盖已有工具。
3. **`Call` 的错误约定**：返回（可包装的）`lingo.ErrNotFound` 表示查无数据、`lingo.ErrForbidden` 表示业务侧拒绝——这两类是正常业务结果，记入审计、不计入熔断；**返回其他错误视为技术故障，计入熔断**。以前用普通错误表示"无权 / 不存在"的实现请改用这两个错误。
4. **审计维护**：即使没有注册工具，`Run` 也每 10 分钟维护审计表（把租约过期的待完成记录标为中断、清理 180 天前的记录）；未执行 0007 时只告警一次。
5. 没有注册工具时，问答（意图解析的提示词与输入、意图回退、会话标题）与 MCP（`tools/list`、`initialize`）的行为与 v0.8.0 相同。

## 回退到 v0.8.0

> 以下依据 v0.8.0 的迁移代码阅读得出，**未实际演练**。

- **保留迁移 0007 及其数据**：不要删除 `lingo_data_requests` 表或 `lingo_schema_migrations` 中 0007 的记录，也不要自行编写回滚 SQL。
- v0.8.0 的 `lingo.Migrate` 只执行它自带的 0001–0006，已执行的 0007 会被跳过；`lingo.CheckMigrations` 会把 0007 列在 `Unknown` 中，不影响 `Ready`。
- 回退后 v0.8.0 不会调用 `Config.Tools`，也不读写 `lingo_data_requests`：业务数据工具停止工作，已有审计记录保留在表中、不再清理。
- 之后再升级到 v0.9.0 时，0007 的校验和不变，`Migrate` 会把它当作已执行跳过，审计记录继续可查。

## 已知限制与未实测项

- **防注入未在真实模型下实测**：已验证工具结果只以数据块传入、回答提示词含防注入规则，并在脚本化模型下验证；真实模型的行为本地不具备验证条件。
- 熔断状态只在当前实例内存中，不跨实例共享。
- 后续改进：参数校验与审计按 `InputSchema` 字段名精确匹配，与 Go JSON 解码不区分大小写的口径不一致（低风险）。
- 测试说明：#50 首次集成测试中既有用例 `TestCreateIssuePermanentFailureMarksAbnormal`（REQ-002）偶发失败、复跑通过，根因未确认，未在本版本处理。

## 升级

```sh
go get github.com/zhouhao4221/lingo@v0.9.0
```

- 升级后执行 `lingo.Migrate(ctx, db)`，应用 0007。
- 检查启动日志中的 `Config.Tools entry ignored`，确认没有工具被意外忽略。
- 确认各工具的 `Call` 已按传入用户二次鉴权，并用 `lingo.ErrNotFound` / `lingo.ErrForbidden` 表示查无数据 / 业务拒绝。
- 业务数据会发给你配置的模型，请按数据合规要求选择模型服务，并用 `Sensitive` 去掉不应外发的字段。
