# v0.3.0（2026-11-22）

新增可选的 `GiteaConfig.RejectRedirects`：开启后，灵工发往 Gitea 的所有请求都不再跟随 HTTP 重定向，令牌只会发往 `BaseURL`。默认关闭，行为与 v0.2.0 相同。产品中文名由「灵问」改为「灵工」，并新增 Logo 资源。公开 API 只增不改，没有新增迁移。

要求：Go 1.24+、PostgreSQL 13+、Gitea 1.22+（同 v0.2.0）。

## 新功能 (Features)

- **禁止 Gitea 请求跟随重定向**（#30，待办 #701，供 GPCM REQ-049 接入）：`lingo.GiteaConfig.RejectRedirects bool`。
  - **默认 `false`**：行为与 v0.2.0 相同，沿用 Go 标准库：最多跟随 10 次重定向；跨主机时去掉 `Authorization`，但同主机、子域和 https→http 降级的跳转仍会带上令牌。
  - **设为 `true`**：作用于全部 Gitea 请求，包括启动自检、建单、评论、标签、附件上传、关闭 Issue、Webhook 注册与测试投递、对账、版本同步和读取机器人账号。
  - **任何 3xx 都拒绝**：不只 301/302/303/307/308，还包括 300、304、305 等 Go 本来不会跟随的状态码；Location 缺失或无法解析时也一样。同主机、子域、跨域和 https→http 降级一视同仁。拦截发生在 Transport 层，跳转目标收不到任何请求，也就收不到令牌和请求体。
  - **3xx 响应体不读取，直接关闭**：服务端慢速发送或停住响应体时，调用也会立即返回，不会等到超时。
  - **不可重试**：按配置错误处理。outbox 任务第一次就置为 `failed`，不会退避重试；`SelfCheck` 对应项为 `error`。
  - **已脱敏**：错误信息只包含方法、路径、状态码和跳转类别（`same-origin` / `subdomain` / `scheme-downgrade` / `cross-origin` / `unknown`），不含跳转地址、Location 原值或令牌。`IssueClose.LastError` 为「Gitea 返回了重定向（HTTP 30x），已按配置拒绝跟随，请核对 Gitea 地址」。
  - **不影响全局**：设置只作用于灵工自己的客户端副本，不修改 `http.DefaultClient` 或 `http.DefaultTransport`。
  - 跳转类别只用于排查，精度有限：跨主机的 https→http 也会归为 `scheme-downgrade`，默认端口也没有归一化。这不影响拒绝跟随、脱敏和不可重试。
  - Gitea API 本身不会返回 3xx。出现 3xx 通常说明 `BaseURL` 配错（少了子路径、http/https 写反）或中间有代理改写，应修正地址，而不是关掉这个开关。

## 其他变更 (Others)

- **产品中文名改为「灵工」**（#26）：英文名 Lingo 和 module 路径不变。下列会出现在 Gitea 或接入方的文案随之更新：
  - 驳回关闭 Issue 时的评论标题（「灵工：该工单已驳回……」）；
  - Issue 中后台评论的署名（「灵工后台」）；
  - 来源标签的描述（「由灵工创建」）；
  - MCP `instructions`。

  已对接仓库中现有的标签描述不会自动更新，只有新建或被自检修正的标签才会用新描述。
- **Logo 资源**：
  - #26 新增 `assets/logo/` 下的可配色 SVG，以及配色示例 `preview.html`；
