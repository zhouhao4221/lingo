# v0.2.0（2026-11-21）

后台人员可驳回已转研发的工单，灵问会经 outbox 关闭关联的 Issue。新增只读的迁移就绪检查，接入方可以在迁移未执行时只禁用反馈入口，不必整站报错。公开 API 只增不改。

要求：Go 1.24+、PostgreSQL 13+、Gitea 1.22+（同 v0.1.0）。

## 新功能 (Features)

- **驳回已转研发工单**（REQ-002）：`RejectForwardedTicket` / `POST /tickets/{id}/reject-forwarded` / MCP `reject_forwarded_ticket`。
  - 权限：reviewer / admin。
  - 可驳回状态：`submitted`、`open`、`in_progress`、`need_info`，以及没有修复记录的 `abnormal`。
  - 不可驳回：已有修复（`fixed` / `released` / `deployed`）、`closed`、`answered`、`merged`，返回 `conflict`。早期版本由 `closed` 转为 `abnormal` 的存量工单，按状态历史判定，同样不可驳回。
  - 原因必填，对提交人可见。驳回后状态为 `rejected`，工单、评论、附件、历史全部保留。
  - 重复或并发驳回只生效一次。
- **关闭关联 Issue**：
  - 驳回时在同一事务内入队 `close_issue`，只关闭工单记录的主 Issue。关闭前，机器人在该 Issue 上留一条驳回原因评论：只署后台人员姓名，不含提交人信息，去重后只留一条。
  - 5xx / 429 / 网络错误按通用退避重试。403、404 等不可重试错误使任务置为 `failed`。Issue 返回 404 时不视为已关闭：这时无法确认 Issue 已删除。
  - 失败原因已脱敏，只含类别和 HTTP 状态码。
- **关闭进度与重试**：`TicketIssueClose` / `GET /tickets/{id}/issue-close` / MCP `get_issue_close` 查看 `none` / `pending` / `done` / `failed` 进度。`RetryTicketIssueClose` / `POST /tickets/{id}/issue-close/retry` / MCP `retry_issue_close` 仅在 `failed` 时重新入队，不会重复入队。
- **回流保护**：驳回后，Gitea 的关闭 / 重开 / 删除、指派、标签、里程碑、对账与 PR 合并都只记审计，不覆盖驳回结论。驳回前已排队的补充评论、标签移除与视角同步不再写入 Gitea。
- **补充评论与驳回的仲裁**：两者在工单行锁下用发送租约串行判定。
  - 驳回先提交时，补充评论及其附件不再外发，并记审计 `comment.withheld`。
  - 补充评论正在外发时，驳回最多等 5 秒，仍未结束则返回 `conflict`（409），稍后重试即可。
- **迁移就绪检查**：`lingo.CheckMigrations(ctx, db)` 在只读事务中对比内嵌迁移与当前 schema。
  - 不建表、不改数据、不取 advisory lock。会等待正在进行的 DDL，调用方应给 ctx 设超时。
  - 返回 `MigrationStatus`（`Ready` / `Applied` / `Pending` / `Changed` / `Unknown` / `MissingTables`）。`err == nil` 时看 `Ready`：未就绪不算错误。`err != nil` 表示检查本身失败。

## 数据库

- 新增迁移 `migrations/0002_comment_send_lease.sql`：`lingo_ticket_comments` 增加可空列 `sending_until`、`withheld_at`，向前兼容。`0001_init.sql` 未改动。
