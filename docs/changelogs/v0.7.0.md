# v0.7.0（2026-11-25）

知识库一期：后台人员直接答复工单时可把答复加入知识库（也可手动新建），用户在知识问答中问"怎么用、为什么、怎么办"时，灵工检索知识库作答并附来源。公开 API 只增不改；新增迁移 `0005_knowledge.sql`，升级后需执行 `lingo.Migrate`。

要求：Go 1.24+、PostgreSQL 13+、Gitea 1.22+（同 v0.6.0）。不需要数据库扩展。

## 新功能 (Features)

- **知识库一期**（#42、#43，REQ-006）
  - **入库**：`AnswerTicketWith(ctx, u, id, TicketAnswer{Answer, Knowledge})` 在答复待确认工单的同一事务内把答复加入知识库（REST `POST /tickets/{id}/answer` 带 `knowledge`，MCP `answer_ticket` 带 `add_to_knowledge`）。默认不入库；问题与答案为空时取工单标题正文与答复原文；入库即生效，建议改写为通用内容；邮箱与手机号替换为占位；内容不合法时答复一并回滚。`AnswerTicket` 不变。
  - **维护**（reviewer / admin，限 `User.Projects`）：`CreateKnowledge`、`UpdateKnowledge`、`DisableKnowledge` / `EnableKnowledge`、`DeleteKnowledge`、`DisableKnowledgeByTicket`（按来源工单停用，如提交人要求删除个人数据）、`ListKnowledge`（可按引用次数排序）；REST `/knowledge`、`/knowledge/{id}`、`/knowledge/{id}/disable|enable`、`/knowledge/disable-by-ticket`。
  - **检索**（所有角色）：`SearchKnowledge`、REST `GET /knowledge/search`、MCP `search_knowledge`。中文二元切词 + GIN 数组索引按重合度排序，关键词包含匹配兜底；来源工单只对能查看它的调用者返回。
  - **向量（可选）**：主模型 `Embed` 可用时，`Run` 后台为新建 / 编辑的条目生成向量，检索时对前 50 条按相似度重排。新增可选接口 `EmbeddingModelNamer` 区分向量模型（内置适配器已实现；未配置 `EmbeddingModel` 时不生成），未实现时按维度区分；换模型后旧向量不参与重排并重新生成。
  - **知识问答**：新增知识类意图（使用方法、原因、怎么办；原先归为超出范围的"功能怎么用"改由知识库回答），检索知识条目与提问人可见的同类工单作答；`Citations` 新增 `knowledge`（条目编号、问题、可见时的来源工单）；只引用、只计数回答实际写到的条目；编造的知识编号（`K` + 数字）改用确定性回答，流式输出不推送；条目停用或删除后历史引用只保留编号。无命中时回复"知识库里还没有相关内容"并引导提交咨询工单。
  - **用量**：作答记为 `knowledge_answer`，生成向量记为 `knowledge_embed`（只记次数）。

## 数据库

- **新增迁移 `migrations/0005_knowledge.sql`**：表 `lingo_knowledge`（问题、答案、项目 / 仓库、来源与来源工单、状态、引用次数、检索词 `text[]`、可选向量 `real[]` 与向量模型）。0001–0004 未改动。
- **升级需执行迁移**：在发布流程中调用 `lingo.Migrate(ctx, db)`，可先用 `lingo.CheckMigrations` 确认就绪。0005 随本版本发布，之后不再修改。

```sh
go get github.com/zhouhao4221/lingo@v0.7.0
```

- `Citations` 新增 JSON 字段 `knowledge`；对返回结构做严格校验的客户端请允许该字段。
- 自定义 `Model` 想让知识库使用向量时，实现 `Embed`，可选实现 `EmbeddingModelNamer`；不实现 `Embed`（返回错误）时只用切词检索。
