# v0.11.0（未发布，草稿）

反馈管理列表与历史评论重新同步（GPCM #787 依赖）：
- 新增公开 `ListTickets` 与 REST `GET /tickets`，接入方后台可按项目、状态、类型、关键词等筛选、分页浏览工单
- 新增 `ResyncTicketComments` 与 REST `POST /tickets/{id}/comments/resync`，切换 `ReplyAll` 后可回补此前已存为内部的 Gitea 评论

公开 API 只增不改；**无数据库迁移**；不新增权限规则；默认 `ReplyMode` 仍为 `marked`。

要求：同 v0.10.0（Go 1.24+、PostgreSQL 13+、Gitea 1.22+）。

## 新功能 (Features)

- **反馈管理列表**（REQ-010，待办 #788）
  - **Go**：`func (l *Lingo) ListTickets(ctx context.Context, u User, f TicketListFilter) (TicketPage, error)`
  - **筛选** `TicketListFilter`：`Project`、`Repo`（owner/name）、`Type`、`Statuses`（任一）、`Keyword`（空白分词，各词同时命中标题或正文，最多 10 个、每个 ≤100 字）、
    `Mine`、`IncludeShared`（仅 external）、`TimeField`（created / updated / forwarded）+ `From` / `To`、`BeforeID`、`Limit`（默认 50，最多 200）。
  - **返回** `TicketPage{Tickets []Ticket, Total int, NextBefore int64}`：新的在前；`Total` 不受分页影响；`NextBefore` 为 0 表示没有下一页。
  - **REST**：`GET /tickets?project=&repo=&type=&status=a,b&q=&mine=&shared=&time_field=&from=&to=&before=&limit=` → `{"tickets","total","next_before"}`；
    参数不合法 400，未认证 401，角色未知或 external 无用户 ID 403。
  - **REST 参数格式**：
    - `status`：逗号分隔，表示任一（重复的去重），取值同 `Ticket.status`
    - `q`：按空白拆词，最多 10 个、每个最多 100 字，各词须同时命中标题或正文（不区分大小写）
    - `mine` / `shared`：只接受 `true` | `false` | `1` | `0`，缺省为 false，其他取值 400
    - `time_field`：`created`（默认）| `updated` | `forwarded`；`forwarded` 不传 `from` / `to` 时只含已转出的
    - `from` / `to`：RFC 3339（如 `2026-11-01T00:00:00Z`，带时区偏移时 `+` 需 URL 编码为 `%2B`），`to` 不含
    - `before`：上一页的 `next_before`（首页省略或 0）；`limit`：默认 50，最大 200（超出按 200）
    - `project` / `repo` / `type`：项目 key、`owner/name`、`consult` | `bug` | `feature`
  - **可见范围**：external 默认只含本人（`IncludeShared` / `shared=true` 另含 `TicketAudience` 同事工单，只读）；agent 只含 `User.Projects` 内已转出的；
    reviewer / admin 为 `User.Projects` 内全部（为空时为 `Config.Projects` 全部）；范围外项目返回空页。

- **历史评论重新同步**（REQ-011）
  - **Go**：`func (l *Lingo) ResyncTicketComments(ctx context.Context, u User, id int64, o CommentResyncOptions) (CommentResync, error)`；
    `CommentResyncOptions{Notify bool}`；`CommentResync{TicketID, Repo, Issue, Fetched, Bot, Added, Updated, Unchanged, Skipped, Published, Unpublished, Notified}`。
  - **REST**：`POST /tickets/{id}/comments/resync`，body 可省略或 `{"notify":true}`，200 返回上述计数
  - **错误码**：403（非 reviewer / admin，先于查找）、404（不存在或不在 `User.Projects`）、409（无关联主 Issue、Gitea 未配置、机器人账号未就绪、Issue 已删除）
  - **用途**：定时对账游标只前进，切换 `ReplyMode = ReplyAll` 前已保存为内部的评论不会自动回补；对每张已转出工单调用一次即可（可配合 `ListTickets` 分页）。
  - **处理逻辑**：按当前 ReplyMode 重读该工单主 Issue 的全部评论，与 Webhook / 对账同一套处理：
    - 跳过机器人评论，按 Gitea 评论 ID 去重
    - 编辑写回；旧版本不覆盖；灵工已记为删除的不恢复；对外改内部时清除变更流正文
    - 只写入该工单
  - **默认不通知**（不发 `ticket.comment` 事件），幂等（重复调用全部计入 `unchanged`）；只读 Gitea，不推断删除

- **回补前须知**（用户已确认）：
  - 保留既有可见范围与驳回处理规则
  - 回补前由接入方核查历史评论（ReplyAll 下回补后，提交人会看到该 Issue 上全部非机器人评论）；不适合公开的工单先不执行回补，敏感内容处置另行确认（不以删改历史评论作为默认操作）
  - 首次回补静默执行（`notify` 省略或为 false）
  - 接受之后切回 `marked` 再调用时普通评论改为内部的语义
  - 回补只在接入方环境由其自行执行

## 行为变化

- 现有接口与 MCP 工具不变；`GET /tickets` 原先未注册（只有 `POST /tickets`），现在返回列表；新增 `POST /tickets/{id}/comments/resync`。
- 内部：`ticket.CommentUpdate` 新增 `TicketID`、`Silent`，零值时 Webhook 与对账的行为不变。
- Webhook / 对账遇到灵工已删除的评论、或乱序到达的旧编辑时，评论本来就不会写入；现在也不再记一条审计（`lingo_ticket_events` 中的 `comment.edited`），不发通知的行为不变。

## 数据库

- 无迁移。

## 回退到 v0.10.0

- `go get github.com/zhouhao4221/lingo@v0.10.0` 后重新部署即可；回退前让接入方后台停止调用 `GET /tickets` / `ListTickets` 与 `POST /tickets/{id}/comments/resync` / `ResyncTicketComments`（v0.10.0 没有这些方法与路由）。
- 已回补为对外的评论保持对外（v0.10.0 照常读取），不需要处理数据。

## 已知限制

- `ResyncTicketComments` 按工单逐张调用，无批量接口；不根据 Gitea 列表中缺少某条评论推断删除（删除以 Webhook 为准）；对外判定按调用时的 ReplyMode，若之后改回 `marked` 再调用，普通评论会改为内部。
- 列表无 MCP 工具；排序固定为新的在前（ID 降序）；`Total` 与列表分两次查询，并发写入时可能略有出入。
- 关键词为 ILIKE 子串匹配，项目工单量很大时较慢（与知识问答检索相同）。
