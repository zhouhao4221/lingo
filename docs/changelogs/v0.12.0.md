# v0.12.0（未发布，草稿）

模型内容策略（防御性数据最小化，REQ-012，待办 #793）：
- 新增显式启用的 `Config.ModelContent = lingo.ModelContentMarked`：模型准入与用户可见（`ReplyMode`）分开，external 问答与结案工单自动抽取只把
  ReplyMarked 范围内的评论交给模型；问答检索、知识向量、会话历史与回答候选只用来源可信的内容
- 新增 `ReextractTicketKnowledge` 与 REST `POST /tickets/{id}/knowledge/reextract`，手动按新规则为来源未知的旧抽取知识重新抽取待审核候选

公开 API 只增不改；**数据库迁移 0009**（只加可空列、拆分抽取候选唯一索引，不改写已有行）；默认不启用，既有行为不变。

要求：同 v0.11.0（Go 1.24+、PostgreSQL 13+、Gitea 1.22+）。

## 新功能 (Features)

- **模型内容策略**（REQ-012）
  - **Go**：`type ModelContentPolicy string`（`ModelContentDefault = ""`、`ModelContentMarked = "marked"`）；`Config.ModelContent`；其他取值 `New` 报错。
  - **启用后**：
    - Gitea 评论按同步时原始正文的 `/reply` / `<!-- lingo:public -->` 标记判定是否准入（与 ReplyMode 无关），Webhook、定时对账、`ResyncTicketComments`
      一致；乱序旧版本与已删除的不覆盖；升级前同步、尚未重新判定的不准入。灵工本地的提交人补充、后台答复、MCP 回复照常准入。
    - external 工单问答只带准入的评论；reviewer / admin / agent 的已授权范围不变。
    - 知识问答检索与向量生成只用 `KnowledgeEntry.ModelInput` 的条目（人工填写的 manual / ticket_answer / ticket_comment，或按可信内容生成的派生条目）；
      其他条目照常展示、审核、维护，已有向量保留。
    - 会话历史按助手消息的三档内容范围回放：`marked` 对所有角色回放；`authorized`（只因已授权的内部评论）只对 reviewer / admin / agent
      回放；`untrusted` 与未知（升级前、失败或被旧版本改写过的回答）对所有角色都不回放，以“（此条回答已省略）”占位，引用的知识也不交给模型
      （引用的工单与版本保留）。
    - 自动抽取只用准入的评论；回答“有帮助”候选只有回答为 `marked` 时可信（`authorized` / `untrusted` 为不可信，未知为来源未知）。
  - **未启用**：交给模型的内容与 v0.11.0 相同，只额外记录来源（新列）。
  - **`KnowledgeEntry.ModelInput *bool`**（JSON `model_input`）：只在维护接口返回。
  - 评论与助手消息的判定与写入时的版本绑定（updated_at + 正文 md5），被旧版本改写过的按未知处理；助手消息记录三档内容范围
    `marked` / `authorized`（reviewer / admin / agent 已授权的内部评论，只对这些角色回放）/ `untrusted`（不回放）。

- **按新规则重新抽取**（REQ-012 方案 A）
  - **Go**：`func (l *Lingo) ReextractTicketKnowledge(ctx context.Context, u User, ticketID int64) (KnowledgeReextract, error)`；
    `KnowledgeReextract{TicketID, Outcome, Entry, Comments, Excluded}`，`Outcome` 为 `KnowledgeReextractCreated` | `Exists` | `Skipped`。
  - **REST**：`POST /tickets/{id}/knowledge/reextract` → 200 / 401 / 403 / 404 / 409 / 501。
  - 仅 reviewer / admin、限 `User.Projects`；只适用于已结案的 Bug / 需求且已有来源未知或不可信的抽取条目；旧条目不改；新候选待审核；
    已有可信候选时返回它且不调用模型；只手动触发；与自动抽取共用租约，同一工单并发时后到的等待后返回 exists。
  - 自动抽取遇到已有任何抽取条目的工单不再调用模型（每张工单只自动抽取一次）。

## 数据库迁移

- `0009_model_content.sql`：`lingo_ticket_comments.model_marked` / `model_marked_at` / `model_marked_md5`、`lingo_assistant_messages.model_scope` /
  `model_scope_at` / `model_scope_md5`、`lingo_knowledge.model_ok`（可空，不回填）；
  重建 `lingo_knowledge_extract_ticket_idx`（`model_ok IS NOT TRUE`）并新增 `lingo_knowledge_extract_trusted_idx`（`model_ok`）。
- **锁表**：唯一索引以非 CONCURRENTLY 方式重建，执行期间短暂阻塞 `lingo_knowledge` 的写入（表通常很小），请在发布窗口执行。
- 与 v0.11.0 同时运行兼容：旧版本写入的新列为 NULL（来源未知）。**启用 `ModelContentMarked` 前先完成全部实例升级**（旧实例仍按旧规则把内容交给模型）。

## 升级提示（GPCM）

1. 全部实例升级并执行 `lingo.Migrate`
2. 配置 `ModelContent: lingo.ModelContentMarked`（`ReplyMode` 保持 `ReplyAll`）
3. 需要时逐张 `ResyncTicketComments`（`Notify=false`）重新判定升级前同步的评论
4. 对来源未知的旧抽取知识按需逐张 `ReextractTicketKnowledge`，新候选走正常审核
