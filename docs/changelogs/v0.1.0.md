# v0.1.0（2026-11-21）

灵问的首个版本：可嵌入 Go 库，工单流程端到端可用——用户提交咨询 / Bug / 需求，经后台确认后由机器人在 Gitea 建 Issue，
研发处理、修复、发版、上线的进展回传接入方。知识问答（`Ask`、知识库）尚未实现。

要求：Go 1.24+、PostgreSQL 13+、Gitea 1.22+（Gitea Actions 上线信号需 1.25+）。

## 新功能 (Features)

- **公开 API**：Go 方法、REST `Handler`、`MCPHandler`（Streamable HTTP，16 个工具）、`WebhookHandler`、`Run`、`Migrate`、`SelfCheck`，三个入口能力对齐
- **反馈工单**：咨询 / Bug / 需求，支持文字、Issue 表单模板字段、截图与附件（灵问只存附件引用，文件由接入方的附件系统保存，可经 `Config.FetchAttachment` 读取后上传到 Gitea）；`GET /ticket-types` 供弹窗渲染表单
- **后台确认**：按项目与类型的自动 / 手动转出开关（运行时可覆盖）；转出（可改标题、类型、仓库并勾选附件）、直接答复、合并、驳回；待确认超时提醒
- **Gitea 对接**：机器人按仓库表单模板建 Issue（隐藏标记查重、标签补齐、默认指派）；用户补充与研发回复双向同步（`/reply`、MCP `reply_ticket`）；
  Issue 指派、标签（need-info）、里程碑、关闭 / 重开回流；PR 合并识别修复（含跨仓库）
- **版本与上线**：同步 Release 与版本号 tag，按修复提交是否包含在版本中关联工单（released）；部署工作流、提交状态或 `MarkDeployed` 识别上线（deployed）
- **需求多视角补充**（REQ-001）：固定视角使用者 / 业务方 / 专家 / 决策者（`User.Perspective`，由 `Authenticate` 映射，与权限无关）；需求工单可由各视角追加补充（`AddPerspective` / `ListPerspectives`、`POST|GET /tickets/{id}/perspectives`、MCP `add_perspective` / `list_perspectives`），转出前后均可；Issue 正文按视角分段（标注姓名与时间、内容以引用块渲染防伪造）并打 `<前缀>/视角/<视角名>` 标签，转出后补充由机器人重写区块并发提示评论；必填视角（`Config.RequiredPerspectives`，`Project` 可覆盖）缺失时标注并发 `ticket.perspective_missing`；新增事件 `ticket.perspective_added`，`Event.Perspectives` 供接入方按视角分发通知
- **数据表**：13 张表，统一 `lingo_` 前缀，与接入方业务表共用数据库也不会重名
- **建单整理**：可选的轻量模型（`Config.LightModel`）在建 Issue 前生成清晰标题、从描述中抽取模板字段、整理描述，按模板逐项校验并保留原始描述；失败时按原内容建单
- **内置模型**：`NewOpenAIModel`（OpenAI 及任意兼容接口）、`NewDeepSeekModel`；标准库 HTTP 实现，不引入 SDK；`Config.Model` 改为可选
- **用量与缓存**：每次模型调用记录 token 用量（含命中服务端前缀缓存的部分），`LLMUsage` / `GET /usage` / MCP `get_llm_usage` 按天、用途、模型汇总；提示词保持稳定前缀；进程内缓存统一过期时间与容量上限
- **进展通知**：事件经 outbox 至少一次、按工单顺序投递给 `Notifier`；`ListEvents` / `GET /events` 变更流（游标不漏事件）；被合并工单的提交人随目标工单收到进展
- **可靠同步**：Webhook 验签、两层去重、异步处理；定时对账补齐漏掉的投递；启动自检（版本、权限、标签、Webhook 测试投递、模板、工作流）与 Webhook 自动注册；多实例运行安全
- **数据隔离**：按用户 ID、固定角色（external / agent / reviewer / admin）与项目隔离；提交人身份不写入 Gitea（例外：需求视角区块中的补充人与提交人姓名）。视角补充的权限由 `Config.AuthorizePerspective` 决定，未配置时同工单可见范围（external 只能补充 / 查看本人的需求）
